# yudonKnow — 설계 정본 v0.1

> 선배는 떠나도, **판단**은 남는다.
> 퇴직과 함께 사라지는 것은 문서가 아니라 **상황을 읽는 눈**이다.

---

## 1. 문제를 정확히 짚기

링크드인에서 "Institutional Knowledge Loss / Brain Drain" 으로 반복되는 그 문제인데,
현장에서 실패하는 지점은 늘 같다.

| 통념 | 현실 |
|---|---|
| "퇴직 전에 인수인계 문서를 쓰게 하면 된다" | 전문가는 **자기가 뭘 아는지 모른다**. 20년 몸에 붙은 판단은 질문받기 전엔 언어화되지 않는다 |
| "위키/노션에 다 적혀 있다" | 적힌 것은 **절차**다. 잃는 것은 **예외 처리와 판단 근거**다 |
| "사내 챗봇에 문서를 다 넣자(RAG)" | 없는 지식을 그럴듯하게 지어낸다. 신입은 **틀린 답을 검증할 능력이 없어서** 그 챗봇을 못 믿는다 |
| "도제식으로 붙여두면 된다" | 6개월 남은 사람에게 3년짜리 도제를 붙일 수 없다 |
| "동기가 없어서 안 남긴다" | **남기고 싶어 하는 사람도 못 남긴다.** "설명해 보세요" 앞에서 "그냥 보면 압니다"로 끝난다. 부족한 건 의지가 아니라 **연장**이다 |

그래서 이 도구의 설계 목표는 "문서를 잘 쓰게 하는 것"이 아니다.

> **⓪ 본인이 판다 (연장을 쥐여준다 — 운전대는 전문가가 잡는다)**
> **① 질문으로 캐낸다 (전문가는 쓰지 않는다, 답만 한다)**
> **② 판단 단위로 굳힌다 (문서가 아니라 카드)**
> **③ 분신으로 살려둔다 (읽히는 게 아니라 대화한다)**
> **④ 모르는 것은 모른다고 말하고, 그 공백을 전문가에게 되돌린다**
> **⑤ 쓰인 흔적을 전문가에게 되돌려준다 (보람 = 지속 참여의 유일한 연료)**

⑤ 가 이 프로젝트의 진짜 승부처다. 이런 도구가 죽는 이유는 기술이 아니라
**전문가가 3회차에 인터뷰를 그만두기 때문**이다. 공짜로 자기 무기를
회사에 넘기라는 요구는 오래 못 간다. "내 분신이 이번 주 후배 4명을 도왔고,
라인 정지 1건을 막았다" 가 보이면 그때부터 스스로 채운다.

## 2. 한 문장 정의

> **yudonKnow 는 자기 지식을 남기려는 전문가에게 **암묵지를 스스로 파낼 연장**을
> 쥐여주고, 파낸 판단을 카드로 굳혀, 그 카드로만 말하는 분신(alter)을 남겨,
> 후배가 대화로 물려받게 하는 승계 도구다.**

**"인터뷰 도구"가 아니라 "발굴 도구"다.** 이 구분이 제품의 전부다.
사용자는 설득해야 할 사람이 아니라 **이미 남기고 싶어 하는 사람**이고,
그에게 부족한 것은 동기가 아니라 **꺼내는 연장**이다.
연장 12개의 정본은 [`self-excavation.md`](self-excavation.md).

이름 그대로다. 후배가 *모르는 것(you don't know)* 을 선배의 분신은 안다.
그리고 분신도 모르는 것은 — **모른다고 말한다.** 그게 이 도구의 신뢰 기반이다.

## 3. 핵심 개념 5개

### 3.1 판단 카드 (Judgment Card) — 원자 단위

문서도 Q&A 도 아니다. **하나의 상황 판단**이 하나의 카드다.

```
제목      플로우마크가 게이트 반대편에만 생기면
상황      사출 성형 / 신규 금형 초도 양산 / 사이클 안정화 전
신호      · 게이트 반대편에만 물결무늬
          · 사출 압력 그래프 초기 피크가 평소보다 느슨
          · 금형 온도계 표시는 정상 (여기서 대부분 속는다)
판단      금형 온도 문제가 아니라 **초기 사출 속도 부족**이다
조치      1) 1단 속도 +8% → 2) 30샷 관찰 → 3) 안 잡히면 게이트 단면 확인
근거      온도가 원인이면 전면에 고르게 나온다. 한쪽만 = 흐름 선단 문제
예외      · 재생재 비율 30% 넘으면 이 규칙 안 통한다
          · 겨울철 첫 가동 2시간은 온도 원인일 수 있다
실패담    2019년 이 판단으로 속도만 올리다 게이트 마모를 놓쳐 금형 수리 2주
말로 안 되는 것   "느슨하다"는 그래프 감각 — 화면 녹화 필요 (도제 항목)
위험도    상   |   영역   사출/성형불량
```

- **`신호(cue)` 와 `예외(exception)` 가 이 카드의 존재 이유다.** 절차서에는
  절대 안 적히고, 그게 없으면 후배가 못 쓴다.
- **`말로 안 되는 것(unspeakable)` 칸을 반드시 남긴다.** 암묵지 병목은
  이 도구가 푸는 문제가 아니다 ([reuse-map](reuse-map.md) — coral `spec §4` 와
  동일한 정직성 규약). 담기지 않는다는 사실 자체를 **기록해서 도제 항목으로
  이관**한다. 여기를 얼버무리면 "다 캤다"는 착각만 남는다.
- 카드는 `docs/reuse-map.md` 대로 **H2A2H2 / coral 의 P→I→C 포맷과 호환**된다
  (`상황·신호 → premise`, `판단·근거 → inference`, `조치 → conclusion`).
  같은 온톨로지 위에서 다른 도구와 붙을 수 있게.

### 3.2 발굴 인터뷰 (Elicitation) — 전문가는 쓰지 않는다

AI 가 묻고 전문가는 **말로 답한다.** 질문 순서가 곧 방법론이며,
[`docs/elicitation-protocol.md`](elicitation-protocol.md) 에 5단 사다리로 정본화했다.
전문가가 백지에서 시작하는 순간 이 프로젝트는 실패한다.

### 3.3 분신 (Alter) — 남는 형태

후배는 문서를 검색하지 않는다. **선배에게 묻듯이 묻는다.**

분신의 3대 규약 (코드로 강제, 되돌리지 말 것):

1. **카드 밖으로 나가지 않는다.** 근거 카드 없이는 한 문장도 만들지 않는다.
   일반 LLM 상식으로 메우면 그 순간 이 도구는 사내 챗봇이 되고 신뢰를 잃는다.
2. **항상 근거를 옆에 편다.** 답 옆에 인용 카드가 뜨고, 카드에는
   *언제 어느 인터뷰에서 나온 말인지* 와 *현장 검증 여부* 가 붙는다.
3. **사칭하지 않는다.** 화면에 뜨는 이름은 "홍길동 수석" 이 아니라
   **"홍길동 수석의 분신"** 이다. 사람인 척하지 않고, 확신도를 표기하고,
   모르면 모른다고 한다.

### 3.4 공백 (Gap) — 되돌아가는 화살표

분신이 답 못 한 질문은 버려지지 않고 **전문가의 큐에 쌓인다.**

```
후배 질문 → 분신 검색 → 확신도 < 기준 → 답변 거절 + 공백 티켓 생성
                                              ↓
                            전문가 홈 "후배가 물었는데 제가 못 답한 것 3건"
                                              ↓
                                   다음 인터뷰의 첫 질문이 된다
```

**이게 이 설계에서 가장 값싸고 가장 강력한 부품이다.** 인터뷰 주제를
컨설턴트가 정하는 게 아니라 **현장의 실제 수요가 정한다.** 우선순위는
`질문 빈도 × 위험도 × 남은 재직 기간의 역수` 로 자동 정렬된다.

### 3.5 유산 원장 (Legacy Ledger) — 보람의 회계

전문가 화면에 항상 떠 있는 것:

```
이번 주 당신의 분신
  · 후배 7명이 23번 물었습니다
  · 그중 19번을 당신의 카드로 답했습니다
  · "도움됐다" 14 · "안 맞았다" 2  ← 2건은 카드 교정 요청으로 큐에 있습니다
  · 김대리가 당신의 #34 카드로 야간 라인 정지를 막았다고 보고했습니다

누적
  살아있는 카드 87 · 현장 검증된 카드 31 · 당신을 인용한 판단 412회
  당신이 없었으면 몰랐을 사람 14명
```

- 이것은 인사평가 도구가 **아니다.** 감시로 쓰이는 순간 발굴이 멈춘다.
  ([roadmap](roadmap.md) §거버넌스 — 원장은 본인과 본인이 지정한 사람만 본다.)
- 정량 신호는 조회수 같은 대리변수를 쓰지 않는다. **후배의 명시적 적용
  보고(닻)** 와 **인용** 만 센다. (CAMS-KnowledgeNet 의 "대리변수 금지" 원칙 이식.)

### 3.6 자기 발굴 도구함 (Instruments) — 의지를 받아내는 장치

전문가는 "인터뷰 대상"이 아니라 **채굴자**다. 홈에 도구함이 상시 열려 있고,
오늘 무엇으로 팔지는 **본인이 고른다** (AI 는 추천만).

```
🔨 순간 포착   ⚖️ 오답 채점기   🔍 대조 짝     👂 감각 사다리
📷 가리키기    🗣 소리내어 하기  🥊 분신과 논쟁  ✉️ 후계자에게
📉 회한 채굴   🎚 경계 슬라이더  🗺 머릿속 지도  🌡 암묵지 온도계
```

정본: [`self-excavation.md`](self-excavation.md). 그중 설계에 직결되는 셋:

- **오답 채점기** — AI 가 *그럴듯하지만 틀린* 판단을 내놓고 전문가가 반박한다.
  사람은 자기 지식은 설명 못 해도 **남의 오답은 3초 만에 잡아낸다.**
  백지 대비 발굴 효율이 가장 높은 연장이라 도구함 기본 노출 2개 중 하나다.
- **대조 짝** — 거의 같은 두 사례를 놓고 "무엇이 다른가"만 묻는다.
  **판별 신호(cue)는 비교에서만 튀어나온다.**
- **감각 사다리** — "그냥 감으로"를 눈/귀/손/냄새/타이밍/리듬 6채널 + **비유**로
  쪼갠다. 비유 칸이 핵심이다. 그래도 안 나오면 `unspeakable` 로 정직하게 남긴다.

그리고 연장보다 먼저 오는 것이 **통제권**이다. 내 지식의 처분권이 나에게 없으면
사람은 깊이 파지 않는다 — 가장 값진 판단일수록 그렇다.

| 장치 | 내용 |
|---|---|
| **봉인 (sealed)** | 지금은 나만, **내가 정한 날에 열린다** (퇴직일 등) |
| **비공개 (private)** | 영원히 나만. 언제든 공개 전환 |
| **지목 공개 (for_whom)** | "이건 김대리한테만" — 대상이 구체적일수록 말이 나온다 |
| **내보내기** | 내 카드 전량 반출. **회사가 아니라 내가 저자다** |
| **분신 정지** | 내 분신이 헛소리하면 내가 끈다 |

초대 첫 화면의 첫 문장은 기능 소개가 아니라 **"당신 것입니다"** 다.

## 4. 한 바퀴 (the wheel)

```
  [전문가]                                      [후배]
     │                                            │
  ①도구함에서 연장을 고른다 ─▶ 파낸다 ─▶ ②카드 초안│
    (순간포착·오답채점·대조짝·감각사다리…)        │
     │                              │             │
     └──③승인/교정◀─────────────────┘             │
                     │                            │
                  살아있는 카드 ──④분신이 인용──▶ ⑤답 + 근거 카드
                     ▲                            │
                     │                       ⑥적용하고 결과 보고 (닻)
                     │                            │
                  ⑧다음 인터뷰 ◀──⑦공백/교정 큐 ◀─┘
                     │
                  ⑨유산 원장에 기록 → 전문가 화면 (보람)
```

**바퀴가 닫히는 증거는 ⑤ 다.** 승인된 카드가 실제로 후배의 답에 인용되지
않으면 이 시스템은 그냥 예쁜 인터뷰 녹취록이다.
`tests/test_one_wheel.py::test_the_wheel_closes` 가 그 화살표를 직접 검사한다.

## 5. 상태 기계 (카드 생애)

```
draft ──전문가 승인──▶ confirmed ──적용 보고 N건 이상 + 부정 보고 없음──▶ anchored
  │                       │                                                  │
  │                       └──"안 맞았다" 보고──▶ contested ──전문가 교정──────┘
  │
  └──전문가 폐기──▶ dormant (삭제 아님 · 부활 가능)
```

- **삭제하지 않는다. 잠복(dormant)시킨다.** 조건이 바뀌어 되살아나는 판단이
  현장에 실제로 있다 (CAMS-KnowledgeNet `tree.py` 의 잠복/부활 규칙 이식).
- `anchored` 만 후배 화면에 **✔ 현장 검증** 배지를 받는다. 배지는 전문가의
  권위가 아니라 **후배의 실측**에서 나온다. 이게 "높으신 분 말이라 맞다"를
  끊는 유일한 장치다.
- `contested` 카드는 숨기지 않고 **논쟁 표시와 함께 그대로 보여준다.**
  "이 판단은 최근 2건에서 안 맞았습니다" 가 답보다 중요할 때가 있다.

## 6. 아키텍처

기존 두 레포에서 검증된 구조를 그대로 가져온다 ([reuse-map](reuse-map.md)).

```
app/core/      의존성 0 순수 파이썬 — 카드·검색·커버리지·유산 원장
               (프레임워크도 DB 도 모른다. 테스트가 강제)
app/capture/   인터뷰어 · LLM 어댑터 (텍스트 in/out 경계만)
app/alter/     분신 — 검색 + 근거 결속 + 공백 판정
app/store/     SQLAlchemy 스키마 + 오케스트레이션 (service.py)
app/web/       FastAPI + JSON API + Jinja 단일 파일 템플릿
```

- **LLM 은 산출물 층위로만 접합한다.** 텍스트 in / 텍스트 out.
  `ANTHROPIC_API_KEY` 가 없으면 stub 으로 떨어지고 **동선은 그대로 돈다**
  (배포가 키에 인질 잡히지 않게 — coral 에서 검증된 규약).
- **공백 판정권은 LLM 에 없다.** 확신도는 `app/core/retrieval.py` 의
  검색 점수로 계산하고, 기준 미달이면 LLM 을 **호출조차 하지 않고** 공백으로
  넘긴다. LLM 에게 "모르면 모른다고 해" 라고 부탁하는 설계는 실패한다.
  `tests/test_core.py::test_gap_decision_never_calls_the_llm` 이 강제한다.
- 저장은 SQLite 기본 / Railway 에 Postgres 붙으면 `DATABASE_URL` 자동 인식
  (`postgres://` → SQLAlchemy 드라이버 URL 정규화 포함).

| `experts` | 전문가 + 말투·원칙 프로필(분신 어투) + 퇴직 예정일 |
| `domains` | 영역 지도 한 칸 (커버리지 계산 단위) |
| `sessions` / `turns` | 발굴 세션과 문답 원본 (**원본은 절대 안 지운다**) + 어느 **연장**으로 팠는지 |
| `cards` | 판단 카드 + 상태 + 위험도 + **암묵지 온도(🟢🟡🔴)** + **공개 범위(공개/봉인/비공개/지목)** |
| `flags` | 전문가가 직접 꽂은 **미개척 깃발** (머릿속 지도) |
| `card_nodes` / `card_edges` | P→I→C 호환 그래프 투영 (외부 도구 접합용) |
| `asks` / `citations` | 후배 질문과 인용 기록 — 유산 원장의 원천 |
| `gaps` | 분신이 못 답한 것 (빈도·위험도 누적) |
| `anchors` | 적용 보고 = 외부 현실 닻 (도움됨/안맞음/사고예방 + 실측치) |
| `ledger_events` | 유산 원장 append-only 이벤트 |

## 7. 의도적으로 안 하는 것 (v0.1)

"미구현"이지 "미완성"이 아니다. 늘리자는 제안은 세미나 합의를 거친다.

- **포인트/보상 경제** — CAMS-KnowledgeNet 에 이미 있지만 v0.1 에 넣지 않는다.
  퇴직 임박 전문가에게 사내 포인트는 동기가 아니다. 동기는 **보람과 이름**이다.
  (P2 에서 사내 제도와 붙일 때 이식: `economy.py`)
- **벡터 DB** — 안 쓴다. 카드 수천 장까지는 이득보다 배포 복잡도가 크다.
  임베딩을 쓰더라도 카드당 벡터는 행에 저장한다 (Pinecone·pgvector 불필요).
- **언어를 넘는 검색** — 안 한다. **카드는 파낸 언어로 산다.** 한국어로 판
  카드는 한국어 질문에만 걸린다. 이유는 넷이다: ① 찾아 줘도 못 읽는다 —
  번역하면 지식이 아니라 요약이 된다, ② 교차 언어 유사도는 같은 언어보다
  낮게 나와 임계값 하나로 둘 다 맞출 수 없다, ③ 언어 때문에 생긴 공백이
  전문가 큐에 섞이면 "다음에 팔 곳" 신호가 망가진다, ④ 실사용에서 후배는
  선배와 같은 언어를 쓴다. 영어 사용자에게는 **영어로 판 전문가**를 붙인다.
  `Expert.lang` · `CardRow.lang` 이 이 결정의 실물이고, 랜딩은 화면 언어로
  판 사람을 앞에 세운다.
- **음성 자동 전사** — 인터뷰는 텍스트 입력으로 시작한다. 녹음 업로드는 P1.
  (전문가가 말하는 편이 훨씬 잘 나오므로 P1 우선순위 1번)
- **SSO/조직도 연동** — 이름 입력으로 시작. P2.
- **권한 모델** — 조직 단위 권한은 P2. 단 **본인 통제권(공개/봉인/비공개/지목)은
  v0.1 필수**다. 이건 기능이 아니라 자발성의 전제조건이라 미룰 수 없다.
- ~~**연장 12개 전량 노출**~~ — **철회(2026-08).** v0.1 은 첫 2주에 2개만 열었다.
  선택지 과부하가 이탈 원인이라는 근거는 지금도 맞지만, 감추는 데 대가가 둘
  있었다: ① 이 도구의 차별점이 연장 12개인데 쓰는 사람이 그걸 모른다,
  ② 오늘 필요한 연장이 잠긴 2개 밖에 있으면 할 수 있는 게 없다.
  이제 전부 보이고, 과부하는 **추천 3개 상한**이 막는다.

## 8. 이 설계가 틀릴 수 있는 지점 (미해결 — 풀렸다고 주장하지 말 것)

1. **암묵지 병목.** 손끝 감각·냄새·소리는 카드에 안 담긴다. 이 도구는 그걸
   *풀지 않고 표시만* 한다. 도제 항목이 전체의 몇 %인지가 이 도구의 정직한
   한계 지표다. → `unspeakable` 필드 · 커버리지 리포트에 별도 집계.
2. **전문가의 자기 편향.** 스스로 중요하다 믿는 것과 후배가 실제 막히는 것은
   다르다. 공백 큐(§3.4)가 이걸 교정하는 장치지만, 후배가 질문 자체를 못 하는
   영역은 여전히 사각이다.
3. **분신의 권위 고착.** 검증된 카드가 늘수록 후배가 스스로 판단하기를
   멈출 위험. 탐색 쿼터와 `contested` 노출로 완화하지만 해결은 아니다.
4. **연장이 의지를 대체하지는 못한다.** 도구함은 "말이 안 나오는" 문제를 줄이지만,
   "팔 시간이 없다"는 문제는 못 푼다. 주 1회 20분을 조직이 보장하지 않으면
   어떤 연장도 안 쓰인다. 이건 제품이 아니라 도입 조건이다 (user-flows §D).
5. **한 사람의 판단이 조직 표준이 되는 문제.** 카드에 반대하는 다른 전문가의
   분신이 생기면 무엇이 옳은가. v0.1 은 두 카드를 나란히 보여줄 뿐 판정하지
   않는다. (CAMS-KnowledgeNet 의 거버넌스/분권 로직이 P2 후보)
