# 계보와 선행 사례 — 우리는 무엇 위에 서 있고 어디서 벗어나는가

> 확인일 2026-08-27.
> **표기 규약:** 【문헌】= 문헌 기반 · 【보간】= 우리 해석 · 【미확인】= 전달받았으나

## 0. 왜 이 문서가 필요한가

레포 규약이다: *"사용자 아이디어를 기존 범주로 분류할 때 차이점 반드시 병기."*
그리고 출품 관점에서도 이게 유리하다 — 심사 40% 가 Innovation & Operational
Utility 인데, **계보를 밝히면 "지어낸 게 아니다" 와 "무엇이 새로운가" 가 동시에**
서기 때문이다. 계보를 숨기면 둘 다 잃는다.

## 1. 방법론 계보 — 암묵지 추출은 이미 정립돼 있다

### 1.1 인지적 과제 분석 (CTA) — 실무에서 가장 정립된 계열

**Critical Decision Method (CDM)** — Klein, Calderwood & MacGregor (1989) 【문헌】

실제 겪은 **비일상적 사건 하나**를 골라 네 번 훑는다:

1. 사건 전개 서술
2. 타임라인 확정·검증
3. 심화 probe — 무엇을 보고 알았나(cues) · 목표 · 고려한 선택지 · 유추한 과거 경험
4. "What if" — 초보라면 여기서 뭘 놓쳤겠나

소방·군·의료·항공에서 검증됐다. **`docs/elicitation-protocol.md` 5단 사다리의
문헌상 정본이 이것이다.**

**ACTA (Applied CTA)** — Militello & Hutton (1998) 【문헌】

CDM 을 현장에서 쓸 수 있게 줄인 4종: Task Diagram / **Knowledge Audit** /
Simulation Interview / Cognitive Demands Table.

Knowledge Audit 의 probe 목록이 특히 실용적이다:
*past & future · big picture · **noticing**(남들이 못 보는 신호) · job smarts ·
improvising · self-monitoring · anomalies · equipment difficulties*

> **`noticing` probe 가 정확히 우리의 `신호(cues)` 칸을 캐는 도구다.**
> 사다리 2단(신호 심문)과 대조해볼 값어치가 있다. → P1 과제

### 1.2 이론적 뿌리

| 출처 | 핵심 | yudonKnow 대응 |
|---|---|---|
| Polanyi, *The Tacit Dimension* (1966) | "we know more than we can tell" | 문제 정의 자체 |
| Klein, RPD 모델 | 전문가는 선택지를 비교하지 않고 **상황을 재인**한다 | **`신호` 없는 카드 인용 불가**의 이론적 근거 |
| Collins, tacit knowledge 3분류 | relational / **somatic** / collective | somatic = 🔴 손끝. 언어로 안 되는 층 |
| Dreyfus & Dreyfus | 숙련 5단계 | 사다리 3단(반사실)의 초보-전문가 대비 |
| Nonaka & Takeuchi, SECI (1995) | 암묵↔형식 변환 4국면 | 유명하지만 **조작화가 약하다.** 실무 도구로는 CTA 가 훨씬 구체적 |

### 1.3 개별 기법

| 기법 | 출처 | 내용 |
|---|---|---|
| Repertory Grid | Kelly (1955) → Shaw & Gaines | 셋을 주고 "둘은 같고 하나는 다르다, 뭐가?" (triad elicitation) |
| Laddering | Hinkle | "왜?"를 반복해 구성개념 위계를 **올라감** |
| Protocol Analysis / Think-aloud | Ericsson & Simon (1984) | 작업하며 소리내어 말하기 |
| Teachback | — | 분석가가 이해한 걸 되말하면 전문가가 교정 |
| Concept mapping | Novak | 개념 그물 |
| CommonKADS | Schreiber et al. | 유럽 지식공학 표준급. **무겁다** |

## 2. 기존 방법론이 *실제로* 어떻게 실행됐나

**방법론의 내용보다 실행 조건이 차이의 핵심이다.** 【문헌 + 보간】

| | 기존 실행 현실 |
|---|---|
| 주체 | 훈련받은 **지식공학자·인지심리학자.** 전문가 혼자 못 한다 |
| 비용 | CDM 인터뷰 1건 2~4시간, **분석은 그 몇 배** |
| 발주처 | 군·소방·항공·원전·의료 — **사고 비용이 극단적으로 큰 조직만** 감당 |
| 산출물 | 보고서 · Cognitive Demands Table · 훈련 커리큘럼 · 전문가 시스템 룰베이스 |

### 두 번의 좌초

**① 지식획득 병목 (전문가 시스템 시대)** 【문헌】
Feigenbaum 이 명명한 그 병목. **방법론이 나빠서가 아니라 룰 하나 뽑는 비용이
너무 비싸서** 상용화가 무너졌다.

**② KM 붐의 실패 패턴 (1990~2000년대)** 【문헌 + 보간】
사내 위키·베스트프랙티스 DB. 반복된 실패 경로:
올리는 사람에게 보상 없음 → 검색해도 상황에 안 맞음 → 문서가 썩음.

**그리고 공통점 하나** 【보간】: **추출까지가 프로젝트였다.**
보고서가 나오면 끝. 후배가 실제 상황에서 그걸 꺼내 쓰는 경로는 아무도 설계하지
않았다.

## 3. 연장 12개 ↔ 문헌 대조

| 우리 연장 | 가장 가까운 기존 것 | **차이** |
|---|---|---|
| 🔨 순간 포착 | CDM 사건 회상 | CDM 은 **사후 회고**, 이건 **당일 판단**. 회상 편향은 줄지만 드문 사건을 못 잡는다 (roadmap P1-5 가 그 보정) |
| ⚖️ 오답 채점기 | teachback + ACTA "What if" + 교육학의 erroneous examples | **문헌에 정확한 대응물이 약하다.** 기존엔 사람이 오답을 준비했고, 여기선 LLM 이 생성하고 전문가는 빨간펜만 든다 — **비용 구조가 다르다.** 실질 차별점 |
| 🔍 대조 짝 | Repertory Grid 의 triad elicitation | repgrid 는 격자로 **정량화**, 이건 격자를 안 만들고 **카드 한 장으로 떨군다** |
| 👂 감각 사다리 | Laddering + Collins 의 somatic | laddering 은 "왜"로 **올라가며 추상화**, 이건 감각 채널로 **내려간다** |
| 🗣 소리내어 하기 | Protocol Analysis (Ericsson & Simon) | 거의 그대로. 차이는 **분절을 기계가 한다**는 것 |
| ✉️ 후계자에게 | — | 대응물 못 찾음. 수신인 지정이 산출량을 바꾼다는 것은 【보간】 |
| 🌡 암묵지 온도계 | Collins 의 somatic tacit knowledge | 문헌은 **개념으로만** 다룬다. 이걸 **운영 지표로 세는** 사례는 못 찾음 |
| ✔ 현장 검증(닻) | — | **KE 문헌에 대응물이 거의 없다.** CTA 는 추출까지 하고 검증은 보통 전문가 리뷰(=권위)로 끝난다. 후배의 적용 보고를 배지 근거로 쓰는 것은 CAMS-KnowledgeNet 계보지 KE 계보가 아니다 |

## 4. 축별 차이 — 기존 실행 vs yudonKnow

| 축 | 기존 실행 | yudonKnow |
|---|---|---|
| 실행 주체 | 훈련된 지식공학자 | **전문가 본인** (연장만 제공) |
| 비용 | 인터뷰 2~4h + 분석 수 배 → 군·원전만 | LLM 이 인터뷰어 → **단가 붕괴** |
| 산출 단위 | 보고서 · 룰베이스 | **판단 카드 1장 = 상황 판단 1개** |
| 소비 경로 | 문서를 **읽는다** | 대화로 **묻는다** (분신) |
| 검증 | 전문가 리뷰 (**권위**) | 후배의 적용 보고 (**현실 닻**) |
| 못 담은 것 | 암묵적 누락 | 🔴 손끝 **명시 집계** |
| 동기 | 발주처가 시킴 | **보람** (유산 원장) |

### 진짜 차이는 방법론이 아니라 두 가지다 【보간】

1. **비용 구조 붕괴.** CDM 이 좋은 줄 몰라서 안 쓴 게 아니다. **비싸서 못 쓴
   것이다.** LLM 이 그 제약을 걷어냈다. 이건 방법론 혁신이 아니라 **경제 혁신**이다.
2. **바퀴가 닫힌다.** 기존은 추출 → 문서에서 끊겼고, 여기는
   인용 → 적용 보고 → 공백 → 재발굴로 돌아온다. **여기가 진짜 미개척지다.**

### 우리가 지불하는 대가 — 감추지 않는다

분석가를 없앤 대신 **분석가가 걸러주던 자기보고 편향 보정이 사라졌다.**
공백 큐가 유일한 외부 교정 장치이고 완전하지 않다 (`docs/design.md` §8-2).

## 5. AI 로 유사 접근한 선행 사례

### 5.1 학술 — 활발하다

**가장 직접적인 것: Investigating Knowledge Elicitation Automation with LLMs**
(Semantic Web Journal) 【미확인 — 원문 확인 필요】

GPT-4 로 지식도출을 자동화해 인간 전문가 인터뷰와 비교했다. 보고된 결론:

- AI 인터뷰가 더 빠르고 구조적
- 그러나 **온톨로지 생성은 사람이 우세** (AI 산출물은 표준화되지만 데이터를 많이 놓침)
- 결론: **하이브리드 — 인터뷰는 LLM, 구조화 판정은 사람**

> ⚠️ **이게 중요하다.** 이 결론이 우리 설계 원칙과 정확히 같다 —
> *"LLM 은 산출물 층위로만 접합한다. 판정을 LLM 에 위임하지 않는다."*
> **문헌이 권고한 하이브리드를 우리는 코드로 강제했다**
> (`test_gap_decision_never_calls_the_llm`). 출품 서사에서 인용 가치가 크다.
> **단, 인용 전에 원문을 확인할 것.**

기타 【미확인 — 전부 원문 확인 필요】:

- **LLMREI** — 요구사항 도출 인터뷰 자동화. 요구사항 73.7% 도출, 실수 빈도는 인간과 유사
- **LLM-assisted repertory grid interviews** (2026) — 🔍 대조 짝의 대응물
- **From Chat to Interview: Agentic Requirements Elicitation** — 경험 온톨로지 기반
- **Craft Practice to Aesthetic Cognition Transmission** — 무형문화재 장인 인지 전승.
  🔴 손끝 영역을 정면으로 다룸

### 5.2 상용 — 많은데 **방향이 반대다** 【보간】

제조 tribal knowledge 계열(UptimeAI · iFactory · Meshnex · Dovient · oxmaint 등)이
이미 여럿 있다. 그런데 대부분 이렇게 한다:

> 작업지시서 · 기술자 노트 · 고장 이력 등 **이미 쌓인 데이터를 분석해**
> SOP · 트러블슈팅 가이드를 자동 생성

**이건 "문서를 파는 것"이지 "사람 머릿속을 파는 것"이 아니다.**
남아 있는 기록에서 추출하니, **애초에 기록되지 않은 것 — 즉 진짜 암묵지 — 은
구조적으로 못 건진다.** 우리 문제 정의(`docs/design.md` §1)의 두 번째 줄이 정확히
이 지점이다.

Digital Twin 계열(personal.ai 등)은 개인 지식 트윈을 만들지만 코칭·영업 쪽이고,
"verified, governed" 를 표방해도 **검증 주체가 불명확하다.**

## 6. 비어 있는 자리 — 우리가 선 곳

【보간 · 확신 중간 — **없다는 것을 검색으로 증명할 수는 없다.** 다음 세션이
반증을 찾으면 이 절을 고칠 것】

1. **후배의 적용 보고로 카드를 검증하는 루프.**
   학술은 추출까지, 상용은 문서 생성까지다. 사용 통계(조회수)는 있어도
   **현실 닻**은 못 찾았다.
2. **못 담은 것(🔴 손끝)의 명시 집계.**
   Collins 의 somatic tacit knowledge 는 개념으로 다뤄지지만, **운영 지표로 세는**
   사례는 안 보인다.

흥미로운 점: **이 두 개 다 KE 문헌 계보가 아니라 CAMS-KnowledgeNet 계보에서 왔다**
(`docs/reuse-map.md`). 우리가 지식공학에 가져온 것은 방법론이 아니라 **검증 경제학**이다.

## 7. 문제 실증 — 공개 제출물에 쓸 수 있는 수치

**이 세션이 직접 확인함** 【문헌 · 확신 높음】

출처: **APQC**, *Navigating the Great Retirement with KM & AI* (eGain 후원),
1,000개 조직 조사.

| 수치 | 내용 |
|---|---|
| **92%** | 퇴직 예정자의 지식을 **일관되게 수집하지 않는다** |
| **58%** | C-suite 응답자가 이 지식 손실을 **매우 우려**한다 |
| **85%** | KM 프로세스 자동화에 **AI 를 운영에 넣지 못했다** |
| **41%** | 퇴직자에게서 노하우 수집을 **"거의 또는 전혀" 시도조차 안 한다** |
| **51%** | 향후 5년 내 퇴직·이탈이 예상되는 인력 비율 |

제조 인력 고령화 【문헌 · 확신 높음】:
미국 제조업에서 **55세 이상 비중이 1995년 약 10% → 약 25%** 로 늘었다
(The Manufacturing Institute). 일부 직군(기계공·용접공·엔지니어·공장장)은
**56세 이상이 40~45%** 인 지역 조사도 있다.

### 이 수치가 왜 제품 주장의 실증인가 【보간】

**92% 가 안 하는데 58% 가 심각하다고 답한다.** 이 갭이 전부다 —
**심각한 줄 알면서 안 한다.** 그리고 85% 는 AI 를 아직 운영에 못 넣었다.
의지가 없어서가 아니라 **연장이 없어서**라는 우리 전제
(`docs/design.md` §1 네 번째 줄)의 바깥 증거다.

## 8. 출품에서 쓰는 순서 (심사 40% 대응)

1. **문제 실증** — 92% vs 58% 갭, 그리고 85%
2. **계보 인정** — CDM/ACTA 위에 서 있다 (지어낸 게 아니다)
3. **왜 지금인가** — 비용 구조가 붕괴했다
4. **문헌이 권고한 하이브리드를 코드로 강제했다** — 판정은 LLM 이 하지 않는다
5. **아무도 안 한 것** — 바퀴를 닫았다 (적용 보고 → 공백 → 재발굴)

> ⚠️ 4번에 논문을 인용하려면 **원문을 먼저 확인할 것.** §5.1 은 전달받은 것이고
> 이 세션이 직접 읽지 않았다. 확인 못 하면 논문 인용 없이 4번을 우리 설계 결정으로만
> 쓴다 — 그래도 논지는 선다.
