## 컴파일러 로드맵 — 암묵지 → 실행 가능한 의사결정 시스템

제품의 최종 정의: **인간의 암묵지를 실행 가능한 의사결정 시스템으로
변환하는 컴파일러.** veTriage 재생산 실험(docs/vetriage-experiment.md)이
전반부(문답→구조→절차 컴파일)를 실증했다. 다섯 층으로 완성한다:

| 층 | 역할 | 현재 (v0.2.x) | P1 |
|---|---|---|---|
| LLM | 인터뷰·발굴·질문 생성·규칙 후보 구조화 | ✅ 사다리·캠페인·정련·**규칙 초안 제안**(v0.3.1, 승인 전 무효) | 모순·빠진 예외 탐색 |
| 전문가 | 규칙 수정·예외 승인·공개 | ✅ 카드 승인·통제권 | 위험도 승인 |
| 결정론 | 승인된 규칙 실행 | ✅ 검색·공백 판정·절차 뷰 컴파일·**판정 엔진**(all_of/none_of/priority/모름=상향, 3상 문진, v0.3.0)·**canonical 신호 ID**(`id :: 문구`, v0.4.1) | 권한 규칙(하향은 전문가만)·required·expected_outcome |
| 감사 | 원문·수정·승인자·사용 기록 | ✅ 원장 append-only·원본 발화 보존 | 규칙 버전 계보 |
| 보상 | 사용된 규칙 ← 제공자 연결 | ✅ 인용·명세서 | 가중 기여 지수 집계 |

실행 단계에서 LLM 은 긴급도를 판단하지 않는다 — **LLM 은 프로토콜을
발견하고, 승인된 결정론적 엔진이 프로토콜을 실행한다.**

**P1 카드 확장 — 규칙 칸 (외부 QA 실측이 준 스펙).** 지금의 신호 목록은
"하나라도 맞으면 열람"이라 완화(GREEN 류) 판단의 게이트로 쓸 수 없다
(v0.2.7 에서 열람 명시·미확인 신호 게이트·충돌 배너로 보수적으로 막았고,
판정 엔진화는 이 칸들이 생겨야 한다):

- `all_of` — 전부 충족해야 하는 조건 (완화 판단의 필수 골격)
- `any_of` — 하나만 있어도 되는 조건 (위급 판단의 골격)
- `none_of` — 없어야 하는 조건
- `required` — 반드시 물어야 하는 확인 질문
- `unknown_action` — 모를 때: 재질문 / 상향 / 중단 (하향 금지 기본)
- `priority` — 판단 간 우선순위 (위급 > 완화)
- `authorized_override` — 하향 조정 권한 (상향은 누구나, 하향은 전문가만)
- `action_sequence` — 순서가 있는 행동
- `expected_outcome` — 검증 사례와 정답 (회귀 케이스)

인터뷰가 이 칸을 채우는 질문("이 중 무엇이 전부 있어야 안심입니까?",
"모르면 어느 쪽으로 기울입니까?")을 얻고, 승인된 규칙은 결정론 코드가
실행한다. 이것이 의사결정표·상태기계로의 컴파일이다.

## 거버넌스 (도입 전에 합의해야 하는 것)

이 도구는 사람의 판단과 실패담을 모은다. 아래를 문서로 약속하지 않으면
전문가는 5단(실패 채굴)에서 입을 닫는다.

1. **실패담은 인사 기록·평가와 연결하지 않는다.**
2. **유산 원장은 개인 성과 지표로 쓰지 않는다.** 본인과 본인이 지정한 사람만 본다.
3. **전문가는 자기 카드의 사본을 가져갈 수 있다.** (퇴직 시 유산 카드 내보내기)
4. **분신은 사람을 사칭하지 않는다.** 항상 "OOO 의 분신"으로 표기하고
   근거 카드를 함께 보여준다. 카드 밖 답변은 하지 않는다.
5. **전문가는 자기 분신을 정지시킬 수 있다.** (오답 누적 시 본인 판단으로 중단)
6. **지식 사용료 (퇴직 후 보상) — 정책 제언.** 선의와 보람은 제품 안의
   엔진이지만, 회사가 이것을 **프로페셔널하게** 돌리려면 퇴직자에게 분신의
   활용만큼 보상하는 정책이 유효하다. 두 형태를 권고한다:
   - **활용 연동 사용료** — 분신의 인용·"도움됐다" 보고에 연동한 소액 정산.
     유산 원장이 조회수·좋아요를 세지 않고 **인용과 명시적 적용 보고만**
     세는 이유가 여기서 힘을 발휘한다: 대리변수가 없어서 원장을 그대로
     정산 근거로 쓸 수 있다.
   - **유급 공백 세션** — 퇴직 후 공백 큐에 쌓인 질문을 채우는 자문 계약.
     퇴직과 함께 바퀴가 끊기는 문제(공백을 채울 사람이 없다)의 답이기도 하다.

   단, 두 경계를 지켜야 한다. ① 정산 기준은 카드 **수**가 아니라 후배의
   실측(도움됐다·✔)이어야 한다 — 수에 걸면 얇은 카드가 쏟아진다. ② 보상은
   원장을 **본인에게 유리하게** 쓰는 것이지 감시로 쓰는 것이 아니다.
   원칙 2(성과 지표 금지)와 충돌하지 않는다: 평가는 회사가 사람을 보는
   것이고, 사용료는 사람이 회사에 남긴 것의 값을 받는 것이다.

   **가중 기여 지수 (권고 산식).** 단순 조회·질문 횟수를 정산에 걸면
   인기 분야와 자극적 기록이 유리해진다. 원장의 사건을 신뢰 등급대로
   가중하는 것을 권고한다 — 인용(낮음) < "도움됐다"(중간) < 현장 검증 ✔
   (높음) < 사고 예방·손실 방지 보고(매우 높음), 여러 후배·현장의 반복
   사용은 추가 가중. "안 맞았다" 는 감점이 아니라 **재검토 신호**다 —
   보고한 후배 덕에 카드가 고쳐지는 것이 이 도구의 순환이고, 감점을 걸면
   전문가가 어려운 판단을 봉인한다. 가중치 숫자 자체는 노사가 정한다 —
   제품은 각 등급의 **횟수를 검증 가능하게 세는 것**까지만 한다
   (명세서가 그 원장이다).

   v0.1 구현: **지식 사용 명세서** — 전문가 홈에서 본인이 뽑는다
   (`GET /api/experts/{id}/statement` · JSON 내려받기). 카드별 인용·도움됨·
   검증·안 맞음 내역과 합계. 단가·금액 칸은 의도적으로 없다 — 계약·단가는
   코드가 아니라 인사 정책이다. 명세서가 관리자 화면에 나가지 않는 것이
   원칙 2 와의 경계다.

---

7. **부재·사후 관리.** 은퇴자가 연락되지 않거나 사망하면 — 분신은
   기본적으로 **계속 답한다** (남긴 판단이 일하는 것이 이 도구의 목적이다).
   단 ① 미지급 정산분은 상속 절차를 따르고, ② 본인이 생전에 지정한
   승계 통제자(가족·지정 후배)가 분신 정지·파기권을 이어받으며, ③ 지정이
   없으면 카드 수정·정지는 동결하고 답변만 유지한다. 계약서 한 줄이면
   되는 문제지만, 계약서에 없으면 분쟁이 되는 문제다.

8. **정산 조작 방지.** 인용이 돈이 되는 순간 자기 인용·품앗이 질문이
   생긴다. 원장이 이미 갖춘 방어: 본인 미리보기는 원장에 안 잡힌다
   (`alter_preview` 는 ask 를 쓰지 않는다), 질문자 신원이 기록된다,
   정산 가중은 인용이 아니라 **후배의 실측 보고** 쪽에 실린다 — 보고는
   질문보다 위조 비용이 높다. P1(SSO)에서 질문자 실명화로 완성된다.

9. **파기권 (본인의).** 카드는 잠복만 있고 삭제가 없는 것은 **지식 무결성**
   원칙이지 본인 구속이 아니다. 전문가 본인이 요구하면 **내보내기 후 전량
   파기**한다 — 원본 발화 포함. "원본 영구 보존" 은 회사·기계로부터의 보존
   약속이지, 저자 자신에 대한 족쇄가 아니다. 절차: 본인 요청 → 전량
   내보내기 제공 → 파기 확인서. (개인정보보호법·GDPR 삭제권 정합.
   v0.1 은 정책 명문화까지, 파기 API 는 P1.)

## 성공 지표 (허영 지표 금지)

### 계기판 (P1 — 측정 훅)

바퀴가 도는지 숫자로 본다. 전부 대리변수 아님:

| 지표 | 정의 | 경보선 |
|---|---|---|
| 활성화 | 온보딩 → 첫 카드 승인까지 시간 | 10분 초과 시 온보딩 재설계 |
| 세션 완주율 | 시작한 발굴 중 승인 도달 비율 | — |
| 얼버무림 후 이탈 | deepen 질문 직후 세션 이탈률 | 높으면 문안이 취조로 읽히는 것 |
| 강등율 | 분신 답 중 인용 검증 탈락 비율 | 높으면 프롬프트/검색 수리 |
| 재방문 | 전문가 주 1회 · 후배 재질문 간격 | 3회차 이탈이 사망 신호 |


| 재는 것 | 안 재는 것 |
|---|---|
| 승인 카드 수 · **신호(cue) 가 채워진 비율** | 인터뷰 시간 총합 |
| 공백 → 채워짐 → **재질문 발생** 건수 | 분신 대화 수(조회수) |
| 적용 보고 수 · 그중 "도움됨" 비율 | 좋아요 |
| **전문가가 스스로 요청한 인터뷰 횟수** ← PMF 신호 | 관리자가 배정한 인터뷰 횟수 |
| `unspeakable` 항목 수 (담지 **못한** 양의 정직한 집계) | 커버리지 % 단독 (천장 0.95 — 100% 는 나오지 않는다) |
